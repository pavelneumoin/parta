# Чек-лист тестирования handwriting-прототипа

## Что тестируем

Это **один HTML-файл** (`handwriting.html`), он отвечает на единственный вопрос:
> Достаточно ли качественен наш рукописный ввод, чтобы строить вокруг него продукт?

Если ответы «да» по всем 5 пунктам из раздела «Критические» — двигаемся дальше, строим Next.js скелет.
Если хотя бы один «нет» — переделываем handwriting (PixiJS / WebGL / своя реализация), потом всё остальное.

## Как запустить

### Вариант А — на компе

Браузер: `http://localhost:8765/handwriting.html` (если сервер уже запущен через Claude Preview).

Если сервер не запущен:
```powershell
cd E:\YA\YandexDisk\Parta\prototype
python -m http.server 8765
```

### Вариант Б — на планшете (тот же Wi-Fi)

1. Узнать IP компа: `ipconfig` → ищем IPv4 адрес локальной сети (обычно `192.168.x.x`).
2. На планшете в Chrome / Safari открыть: `http://192.168.x.x:8765/handwriting.html`
3. Если не открывается — Windows Firewall блокирует порт 8765. Временно разрешить или использовать `ngrok http 8765`.

## Что в HUD

В правом верхнем углу — диагностический оверлей:

| Поле | Что значит | На что смотреть |
|---|---|---|
| FPS | Частота кадров live-рендера | Должно быть стабильно ≥40, в идеале 60 |
| pointer | Тип последнего события | `pen` — стилус, `touch` — палец, `mouse` — мышь |
| pressure | Давление (0–1) | На Apple Pencil и S Pen меняется при нажатии |
| tiltX/Y | Наклон стилуса | Не используем сейчас, но индикатор работы Pointer Events |
| strokes | Сколько штрихов финализировано | Растёт с записью |
| points | Сколько точек во всех штрихах | Чтобы видеть масштаб данных |
| lat ms | Среднее время от первого pointermove до отрисовки финала | Должно быть <30 мс |

Если на каком-то устройстве `pointer` = `touch` для Apple Pencil — это плохо, значит браузер не распознаёт стилус. Тогда нужны TouchEvents-fallback'и.

## Критические тесты (5 пунктов — все должны пройти)

### 1. Stylus first — pointer === 'pen', есть давление

**Что делать:**
- Открыть на iPad с Apple Pencil **или** Samsung Tab с S Pen **или** Windows-планшете с пером.
- Поставить стилус на холст и медленно вести линию.

**Что должно быть:**
- HUD: `pointer = pen`, `pressure` меняется от 0.1 до 1.0.
- Штрих заметно меняет толщину от нажатия.
- `lat ms` ≤ 30.

**Если нет:** проблема железа/драйверов либо нужен фикс Pointer Events для конкретного устройства.

### 2. Palm rejection — ладонь не пишет

**Что делать:**
- Включить «Только перо» (по умолчанию включено, синяя кнопка вверху).
- Положить ладонь на экран ниже линии письма.
- Писать стилусом по обычной траектории.

**Что должно быть:**
- Ладонь **не** оставляет штрихов.
- Стилус пишет нормально.

**Если нет:** нужен дополнительный фильтр через TouchEvents (по `touchType === 'stylus'` на iOS).

### 3. Плавность штриха — нет «лесенки» и дёрганий

**Что делать:**
- Стилусом написать прописью: `f(x) = 2x² + 3x - 5`
- Нарисовать график синусоиды от руки.

**Что должно быть:**
- Линия плавная, без зубчиков, без задержек.
- Концы штриха скруглены.
- Жирные части (нажатие) переходят в тонкие плавно.

**Если нет:** уменьшить `streamline` / увеличить coalesced events / переключиться на WebGL.

### 4. Производительность под нагрузкой

**Что делать:**
- Написать **сплошным письмом 5 минут** разной математики: уравнения, схемы, графики.
- Смотреть на HUD: FPS и lat ms.

**Что должно быть:**
- Когда штрихов 100+ → FPS не падает ниже 40.
- Когда штрихов 500+ → FPS не падает ниже 30.
- Live-рендер текущего штриха никогда не лагает.

**Если нет:**
- Слабое устройство (Lenovo Tab M8) — оптимизировать через offscreen canvas / WebGL.
- Сильное устройство (iPad Pro) — переписать алгоритм рендера, что-то критически плохо.

### 5. Стирание — ластик попадает туда, куда указываешь

**Что делать:**
- Написать 5–6 штрихов в разных местах.
- Нажать «Ластик» в тулбаре.
- Аккуратно провести по одному штриху.

**Что должно быть:**
- Удаляется только тот штрих, по которому провели.
- Соседние штрихи (за пределами ~14px) остаются.
- На Apple Pencil 2 / S Pen с кнопкой ластика — переворачиваем стилус → пишет ластиком автоматически (`pointer = eraser`).

**Если нет:** увеличить радиус, или сделать «удаление сегмента» вместо «удаления штриха целиком».

## Дополнительные тесты (не блокирующие, для уточнения UX)

### 6. Мышь как fallback

- Открыть на десктопе мышью.
- Должно писать фиксированной толщиной (без pressure), плавно.
- В HUD: `pointer = mouse`, `pressure = 0`.

### 7. Палец на тачскрине (для слабых сценариев)

- Выключить «Только перо» (кнопка станет серой).
- Писать пальцем на планшете.
- Должно писать, но качество хуже (нет давления).

### 8. Жесты

- Двойной тап тремя пальцами по холсту → должна сработать **отмена** (всплывает тост «Отмена»).
- Тремя пальцами → **повтор**.

### 9. Цвета и толщины

- Тапы по цветным кругам в тулбаре → меняется цвет штриха.
- Долгое нажатие (~400 мс) по любому цвету → открывается выбор толщины (тонкая / средняя / толстая).

### 10. Подложки

- Кнопка с иконкой сетки → циклирует подложки: клетка → координаты → линии → чистый.

### 11. Экспорт

- Кнопка со стрелкой вниз → скачивается PNG со штрихами и подложкой.
