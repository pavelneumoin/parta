## Контекст: продукт «Парта»

**Что:** веб-приложение для класса. Учитель раздаёт один шаблон (PDF или чистый лист в клетку/линию/координаты) — каждый ученик получает свою копию на планшете. Учитель видит мозаику из 28 листов в реальном времени, может писать красным поверх работы любого ученика или транслировать подсказку всему классу.

**Слоган:** «Видно каждого. Слышно никого.»

**Аудитория:** учителя 1–11 класса, для которых важна **рукописная** работа учеников. Особенно — математики, физики, информатики. **Не** замена Miro/Google Docs/LMS. Конкурирует с бумагой, не с цифрой.

**Ценовая модель:** 590–990 ₽ / мес на учителя.

**Возрастной диапазон пользователей:**
- Учитель (40–60 лет, не айти): должен освоить за 1 урок без обучения.
- Ученик (7–18 лет): должен войти за 5 секунд по QR-коду или 6-значному коду.

## Дизайн-философия и тон

- **«Школа, не TikTok»** — без эмодзи в продукте (только функциональные значки), без анимаций ради анимаций, без gamification.
- **Math-first, stylus-first** — рукопись в первую очередь, набор текста в последнюю.
- **Чистая бумага, не Figma** — фон должен ощущаться как лист в тетради. Не «холст бесконечный», не «вайтборд».
- **Видимая иерархия** — учитель за 1 взгляд понимает: кто рисует, кто завис, кто поднял руку, кто сдал.
- **Без жаргона** — «Завести класс», не «Создать класс». «Идёт сейчас», не «Активная сессия». «Сдать работу», не «Завершить».

## Текущий стек

- Next.js 15 (App Router) + React 19 + TypeScript strict
- Tailwind 3 + кастомная палитра (см. ниже)
- shadcn-ui НЕ используется (минимизируем зависимости)
- handwriting через `perfect-freehand` + Pointer Events API
- SQLite (dev), скоро Postgres

## Текущая палитра (фактическая, из `tailwind.config.ts`)

```ts
{
  paper:        '#ffffff',  // основной фон
  ink:          '#0c0d10',  // основной текст
  chalk:        '#f4f5f7',  // фон холста, hover
  rule:         '#d8dee9',  // тонкие разделители, грид
  accent:       '#4f7cff',  // основной CTA (синий-холодный)
  red:          '#d11a2a',  // штрихи учителя, рука, ошибки
  blue:         '#1f5fc9',  // вспомогательный
  green:        '#2e8b3d',  // submitted, success
  toolbar:      '#1a1f2b',  // тёмная шапка мозаики
  toolbarHover: '#2a3142',
  dim:          '#8b94a8',  // подписи
}
```

Шрифт: системный sans-stack (`-apple-system, BlinkMacSystemFont, Segoe UI, Roboto, …`).

**Известная проблема палитры:** `paper` чисто-белый, не «бумажный». Если предложишь сменить — обоснуй контрастом и эмоциональным тоном.

## Какие экраны существуют

1. **`/` — лендинг.** УТП, скриншот мозаики (mockup), кнопки «Войти» / «Завести класс».
2. **`/signup`, `/signin`.** Простые формы — email, имя, пароль.
3. **`/app` — дашборд учителя.** Секция «Сегодня» (карточки уроков на текущий день с тегом «через 5 мин» / «идёт») + последние уроки + последние классы.
4. **`/app/classes`, `/app/classes/[id]`.** Список учеников, добавление, удаление.
5. **`/app/lessons`, `/app/lessons/new`, `/app/lessons/[id]`.** Создание урока: шаблон (клетка/линия/координаты/PDF), дата, класс. Кнопка «▶ Начать» создаёт сессию.
6. **`/app/session/[id]` — мозаика учителя.** QR-код входа, joinCode 6 цифр, плитки 200×280 с реальными PNG-превью рабочих листов учеников, фильтры (Все / Активные / ✋ Рука / Завис / ✓ Сдали), сортировка, кнопка «↓ Класс ZIP», «Закрыть урок».
7. **`/j/[code]` — экран входа ученика.** Выбор своего имени из списка класса.
8. **`/s/[wsid]` — рабочий лист ученика.** Полноэкранный canvas, инструменты слева (карандаш, ластик, 4 цвета, 3 толщины), кнопка «✋ Поднять руку», «Сдать работу», переключатель страниц. Учитель попадает на этот же URL — UI меняется: красная шапка, дефолт-цвет красный, тогглер «↗ всем / одному», кнопка «↓ PNG».

## Что хочу от тебя

1. **Дизайн-критика** ключевых экранов (`design:design-critique`):
   - Лендинг — он сейчас «инженерный», нужно «педагогическое» спокойствие.
   - Мозаика учителя — самый wow-экран. Хочу, чтобы на нём за 3 секунды считывался статус класса.
   - Лист ученика — нужно, чтобы инструменты не отвлекали от поля.
2. **UX-копирайт** (`design:ux-copy`):
   - Все пустые состояния (нет классов / нет уроков / никто не вошёл).
   - Текст ошибок (неверный пароль, класс уже существует, PDF слишком большой).
   - Confirmation dialogs («Закрыть урок?», «Удалить ученика?»).
3. **Доступность** (`design:accessibility-review`):
   - Контраст всей палитры на бумажном фоне.
   - Размер кнопок для пальца / стилуса (touch target).
   - Клавиатурная навигация для учителя (которая никогда не будет нужна, но WCAG требует).
4. **Дизайн-система**:
   - Token-набор: цвета, типографика (только Inter? добавить Geist Mono для кода?), spacing, radii.
   - Компоненты: Button (3 вариант), Card (плитка ученика, карточка урока), Toolbar, Tile, Tag, Toast.
   - Состояния плитки ученика: not_joined / active / hand_raised / stuck / submitted / closed. Каждое — отдельный визуальный язык, без надписей где можно избежать.

## Что НЕ нужно делать

- Не предлагать gamification (бейджи, очки, прогресс-бары).
- Не предлагать тёмную тему (бумага должна быть бумагой).
- Не предлагать видеозвонки / чат — это вне продукта.
- Не использовать ai-генерированные иллюстрации.
- Не делать редизайн под «AI-product look» (градиенты, glassmorphism, blob shapes). Парта — про спокойную бумагу.

> «Я открыл [URL]. Проведи дизайн-критику этого экрана как для продукта `Парта` (контекст: [одна строчка из секции «Что» выше]). Дай 5 правок в формате «было → стало», с Tailwind-классами под мой стек (tailwind 3, кастомная палитра ink/paper/chalk/rule/accent/red/dim).»

Этого хватит для one-shot улучшений.
